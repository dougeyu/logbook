# 输出格式

选择能满足需求的最小格式。用户提供了公司模板时,严格保留其栏目。

## 公司导师版日报

公司固定的日报格式。用户要"日报/工作日志"且未指定其他模板时使用。姓名/部门/岗位/导师从用户档案读取;首次使用时问一次并记住,之后不再重复询问。

```text
导师、领导您好:
这是我周X的工作日志:

姓名:XXX    部门:XXX    岗位:XX    导师:XXX
日期:YYYY年M月D日

本日工作完成情况

工作进展
1. [动作 + 对象 + 可验证结果];进行中的事项标注当前进展
学习成长
1. [当日学到的概念/技能/领域知识,具体到点,避免"学习了XX"的空话]
遇到的困难及解决方案
1. 困难:[事项——具体阻塞] 解决方案:[已采取或拟采取的动作]
所需资源支持
1. [需要他人/上级提供什么支持,没有则写"无"]
```

该模板的映射规则:

- 工作进展 ← `completed` 与 `in_progress` 事项(进行中的要显式标注)。
- 学习成长 ← `category: "learning"` 的事项;没有则写"无"。
- 遇到的困难及解决方案 ← `blocked` 事项(blocker → 困难,next_step → 解决方案);没有则写"无"。
- 所需资源支持 ← `category: "support"` 的事项;没有则写"无"。
- 该模板没有"明日计划"栏目;昨日遗留通过 `--carry-over` 作为待确认附录呈现。

确定性渲染命令:

```bash
python scripts/render_report.py <items.json> --format company --date YYYY-MM-DD --name <姓名> --dept <部门> --position <岗位> --mentor <导师>
```

## 自定义模板(custom)

每个人的日报/周报模板都可能不同。首次使用时让用户提供部门模板或往期样例,Agent 提取栏目结构后整理为占位符模板文件,之后通过 `--format custom --template <模板文件>` 渲染。参考示例:`assets/report-template.example.md`。

占位符语法:

- 标量(行内替换):`{{date}}` `{{date_cn}}` `{{weekday}}` `{{name}}` `{{dept}}` `{{position}}` `{{mentor}}`
- 列表(独占一行,逐条展开;该段无内容时输出"无"):`{{completed}}` `{{in_progress}}` `{{blocked}}` `{{planned}}` `{{learning}}` `{{support}}` `{{carry_over}}`

模板未覆盖的内容维度不会出现在报告里;占位符写错或缺失时 Agent 应修复模板文件后再渲染。

## 月度 MBO 表格

月初目标表与月末自评表,由 `scripts/mbo_planner.py` 校验并生成。字段规则见 [mbo-rules.md](mbo-rules.md)。Agent 只起草表格文本,用户手动录入内网 HCM 系统。

## 标准日报

```markdown
# 工作日报|YYYY-MM-DD

## 今日完成
- [动作 + 对象 + 可验证结果]

## 进行中
- [事项]:当前进展;下一步

## 问题与风险
- [阻塞或风险]:影响;需要的支持/处理动作

## 明日计划
- [具体下一步]
```

空栏目可省略(除非公司模板要求保留)。不把未完成事项挪进"今日完成"。

## 聊天简报

```text
今日完成:...
进行中:...
风险/需协助:...
明日计划:...
```

用于即时通讯场景,或用户要求简短版本时。

## 管理者汇报

```markdown
## 关键进展
- [结果及有依据的价值]

## 风险与决策点
- [风险、影响、需要的决策/支持]

## 下一步
- [动作;负责人/日期仅在有依据时写]
```

以成果和决策需求开头。实现细节只在影响风险或进度时保留。

## 证据附录

仅在用户要求可追溯时添加:

```markdown
## 依据
- [报告事项]:来源类型 + 简要标识
```

不暴露凭据、敏感链接、私密内容或不必要的绝对路径。

## 周报

```markdown
# 工作周报|YYYY-MM-DD 至 YYYY-MM-DD

## 本周成果
- [按目标归组的成果]

## 关键进展
- [进行中的里程碑及当前状态]

## 风险与协同
- [风险/依赖及需要的支持]

## 下周计划
- [具体下一步]
```

重复的日报内容按目标归组。同一事项的多次出现不得重复计为多项成果。

## 空证据响应

```text
我可以先帮你生成日报。请提供今天最关键的工作痕迹即可,例如:
1. 完成或推进了哪些事项?
2. 有什么可确认的结果、进度或测试情况?
3. 是否有阻塞,以及明天准备做什么?

可以直接粘贴零散笔记、任务列表或提交标题,不必提前整理。
```
