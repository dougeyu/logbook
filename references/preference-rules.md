# 自我进化：偏好学习与反馈闭环

skill 在使用中逐步学习用户的个性化偏好，越用越贴合用户风格。借鉴 Hermes Agent 的关键词触发 + 审批卡片机制。

## 核心原则

1. **不偷偷改**：任何偏好的写入都必须经过用户显式确认，绝不自动修改。
2. **关键词触发**：只有检测到长期意图关键词才触发偏好记录，普通反馈不骚扰。
3. **补丁式更新**：新增/修改偏好只改动一行，不全量重写文件。
4. **有界增长**：偏好文件设字符上限（2000 字符），超了自动合并同类项或丢弃低频项。
5. **用户隔离**：个性化偏好默认存在 skill 根目录的 `user-preferences.md`；平台适配入口可覆盖为该平台的用户级 skill 目录。该文件不提交到项目仓库。

## 触发关键词

用户反馈中出现以下任一关键词组合时，检测为**长期偏好**而非一次性指令：

| 关键词 | 示例 |
| --- | --- |
| 以后都… | 「以后都控制在 5 条以内」 |
| 记住… | 「记住，不要写技术细节」 |
| 永远… / 永远不要… | 「永远不要用加粗」「永远用中文标点」 |
| 每次… | 「每次都在前面加上部门名称」 |
| 一直… | 「一直保持这种风格」 |
| 从现在开始… | 「从现在开始用编号列表」 |
| 始终… | 「始终把阻塞项放在最前面」 |

不含以上关键词的反馈（如「这段删掉」「改成 3 条」）视为**一次性修改**，不触发偏好记录。

## 偏好格式

每条偏好占一行，格式为明文规则描述，可加类别前缀：

```text
# user-preferences.md

## 写作风格
- 日报控制在 5 条以内
- 不使用 Markdown 加粗（纯文本场景）
- 用短句，一句一个意思

## 内容偏好
- 先写结果再写过程
- 技术细节用一句话概括，不展开实现步骤
- 阻塞项放在所有已完成项前面

## 格式偏好
- 用编号列表，不用无序列表
- 日期格式用 YYYY-MM-DD

## 读者适配
- 给领导看时省略技术术语
- 给自己看时保留踩坑过程
```

## 反馈闭环

每次生成报告后，按以下流程：

```
生成报告 → 交付用户
           ↓
用户反馈（如有）
           ↓
检测关键词 → 无关键词 → 仅执行修改，不记录偏好
           ↓ 有关键词
弹出偏好建议：「我记下这条规则，下次照办：[具体规则]。OK？」
           ↓ 用户确认
写入 user-preferences.md（补丁方式：只加/改一行）
           ↓ 用户拒绝
丢弃，继续
```

每季度或偏好文件接近上限时，提示用户回顾和整理。

## 偏好加载

每次生成报告前（工作流步骤 1 之前），加载当前平台确定的 `user-preferences.md`（默认是 skill 根目录下的同名文件）。如存在，将其中的规则作为额外约束注入「撰写有据表述」和「排版」步骤。偏好约束的优先级低于用户当次指令、高于默认规则。

## 偏好沉淀（高级）

完成以下复杂任务后，主动询问是否沉淀为工作流偏好：

- 首次完成 MBO 月初目标制定（可记为「MBO 目标制定流程」）
- 首次完成周报（可记为「周报生成流程：聚合 → 归组 → 排版」）
- 用户连续 3 次使用相同的自定义数据源配置

沉淀方式：在 user-preferences.md 的「## 工作流」区段记录步骤概要，下次同类任务自动参考。
