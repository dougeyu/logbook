# 月度 MBO 规则

公司 HCM 流程:① 目标制定 → ② 主管审核目标 → ③ 员工自评 → ④ 主管评价 → ⑤ 结果校准 → ⑥ 结果确认。
月末至月初的一周内完成:当月目标填报、主管审核、上月目标达成自评与主管评价。

**硬性边界:Agent 绝不访问 HCM 系统(仅限内网),绝不上传任何文件。只起草文本,由用户手动复制进 HCM。**

## SMART 填报原则

1. **具体性(Specific)**:目标明确、具体,避免模糊或笼统的表述。
2. **可衡量性(Measurable)**:目标可量化,能通过具体数据衡量是否达成。
3. **可实现性(Attainable)**:根据个人能力、资源和实际情况设定,付出努力能够实现;既不过于理想化也不过于简单。
4. **相关性(Relevant)**:与岗位职责、部门目标和公司发展规划紧密相关。
5. **时限性(Time-bound)**:设定明确的完成时间,落在当月。

## 目标制定的必填字段

| 字段 | 规则 |
| --- | --- |
| 指标名称 | 简明扼要、言简意赅,避免繁琐词汇和长篇大论。 |
| 指标描述 | 对指标的详细解释,让考核者和被考核者对含义的理解一致。 |
| 衡量标准 | 可量化,或有明确的交付物(如次数、金额、完成百分比、交付文档)。 |
| 权重 | 数值;同一月内所有指标权重之和必须恰好为 100%。 |

其他约束:

- 每月指标**不超过 5 项**。
- 按权重从大到小排序。
- 指标只覆盖当月任务与当月应实现的目标。
- "指标类别"在系统中为可选项;用户提供了才填。

## 月初定目标流程

1. 询问(或复用)用户的岗位职责、部门当期重点、上月自评中的遗留项、本月已知交付物。
2. 按字段规则起草 3-5 项指标;每条"衡量标准"必须包含数字、比率或具名交付物。
3. 运行 `python scripts/mbo_planner.py plan <items.json> --month YYYY-MM` 校验,修复全部错误后再交付。
4. 交付表格文本;用户手动复制进 HCM。

## 月末写自评流程

1. 拿到月初的指标(用户粘贴,或复用月初存档的 JSON)。
2. 逐项收集证据:当月日报、周报汇总、Git/WorkBuddy 活动,或用户的直接陈述。
3. "实际值"和"完成百分比"只填有证据或经用户明确确认的内容;其余保留"待填写",绝不编数。
4. "自评说明"写清做了什么;未完成项写明原因与后续计划。
5. 运行 `python scripts/mbo_planner.py review <items.json> --month YYYY-MM` 渲染;交付表格由用户手动录入。

## 与日报的联动

当月日报和周报是自评的主要证据池。起草自评前,建议先用 `scripts/aggregate_weekly.py` 聚合多天工作项,再把成果映射到各项指标。自评中的每一条完成声明都必须能回溯到至少一条证据,与 [report-rules.md](report-rules.md) 的规则保持一致。
