# 角色画像(人设初始化)

不同岗位的关注点不同:同一句"今天推进了项目",对研发要问"测试过了吗",对销售要问"金额多少、到哪一步了"。首次使用时确认用户角色,之后按其画像组织追问与措辞。角色只影响"问什么、怎么写",不影响工作项结构与校验规则。

初始化时确认一次即可;用户角色不明确时用"通用"画像,不强行归类。

## 通用(默认)

- 关注点:完成了什么、进行中进展、阻塞与风险、下一步。
- 追问重点:结果是否可观察?阻塞是什么?下一步动作?
- 措辞:中性、简洁,动作+对象+结果。

## 研发 / 算法工程师

- 关注点:任务进展、缺陷修复、实验与指标、数据构建、代码评审、技术调研。
- 追问重点:测试/回归是否通过?指标变化多少(有来源才写)?是否合并/部署?实验结论是什么?
- 措辞:写清系统、模块、接口名;结果用"通过/修复/提升 X%"(数字必须有出处)表述。
- 典型条目:修复 X 模块缺陷(回归用例通过)、完成 X 数据集构建(N 条,分类规则见 X)、X 实验指标提升。

## 销售 / 商务

- 关注点:客户拜访、商机阶段变化、合同与回款、渠道进展。
- 追问重点:金额多少?阶段从哪到哪?预计成交/回款时间?谁决策?
- 措辞:客户名称(按脱敏要求处理)+ 动作 + 阶段/金额;未完成商机写"进行中"及下一步动作。
- 典型条目:拜访 X 客户推进 X 项目商机(进入方案阶段)、跟进 X 合同回款(到账 X 元)。

## 产品经理

- 关注点:需求梳理、评审结论、原型/文档交付、版本发布、数据分析。
- 追问重点:交付物是否完成(PRDoc/原型)?评审结论是什么?版本是否如期?数据结论?
- 措辞:写清产品/版本/需求名;结果用交付物名称表述。
- 典型条目:完成 X 需求 PRD 并通过评审、X 版本灰度发布(覆盖 X%)。

## 运营

- 关注点:活动执行、数据效果、内容产出、用户反馈处理。
- 追问重点:数据结果如何(对比基线)?反馈处理了多少?活动是否按期上线?
- 措辞:活动/内容名称 + 动作 + 数据结果(有来源)。
- 典型条目:上线 X 活动(首日参与 X 人)、处理用户反馈 X 条。

## 生产 / 质检

- 关注点:检验批次、不良率、异常处理、设备与工艺。
- 追问重点:批次数量?不良率多少?异常是否关闭?
- 措辞:批次/产线/设备名称 + 动作 + 数量或比率。
- 典型条目:完成 X 批次出厂检验(不良率 X%)、X 设备异常处理(已闭环)。

## 角色与模板的关系

角色画像决定"问什么、怎么写",模板决定"长成什么样"。两者独立:同一个人模板可能换(部门调整),角色一般不变。初始化时分别确认,都只需一次。
